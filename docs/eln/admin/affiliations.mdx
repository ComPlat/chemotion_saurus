:::info
This feature is available starting from version 4.0.
:::

When a user suggests a new organization, department, or working group from **Settings → Affiliations** (see [My Affiliations](/docs/eln/ui/affiliations)), it does not enter the shared registry immediately. It is queued for review. This keeps the registry clean and prevents duplicate or misspelled entries.

Open the admin panel and select **Affiliations** from the menu.

![Pending affiliation suggestions with Edit, Approve and Reject actions](/img/eln/affiliations/aff-14-admin-pending-edit.png)

:::tip[Delegating this task]
Reviewing suggestions doesn't have to sit with administrators only. An admin can grant any user the right to review affiliation suggestions — see [Affiliation Approval Rights](/docs/eln/admin/user_management#affiliation-approval-rights) in User Management. A user with this permission sees the same panel described on this page from their own **Settings → Affiliations → Requests** tab, without needing admin access.
:::

## Reviewing the queue

The list is filtered by status with the **Pending**, **Approved**, and **Rejected** buttons. Pending suggestions are the ones awaiting a decision.

Each row shows who submitted it, the proposed organization, department, working group and country, and the submission date. A suggestion may combine existing registry values with one or more new ones — the new values are what you are approving.

## Fix a suggestion before approving

Click **Edit** to open a suggestion for correction before deciding on it. This is useful when a user's entry is close but not quite right — a typo in the organization name, or an organization that should be linked to its ROR entry.

![Edit request modal with ROR organization search](/img/eln/affiliations/aff-15-edit-modal-search.png)

The edit form gives you the same tools available to users:

- **Country** is picked from the fixed country list.
- **Organization** searches the [ROR registry](https://ror.org/) and the existing organizations already in use, exactly like the user-facing search.
- **Department** and **Working Group** are scoped to the selected organization — pick an existing one or type a new value.

![Edit request modal with the organization corrected and department/working group ready](/img/eln/affiliations/aff-16-edit-modal-fixed.png)

Once the fields look right, click **Approve** directly from this dialog. There is no separate save step — editing and approving happen together, so a submitter with a small mistake never needs to resubmit.

## Approve

Click **Approve** (with or without first editing) to accept the suggestion.

- The organization, department, and working group are added to the shared registry (existing entries — including case and accent variants, and organizations already linked to the same ROR identifier — are reused, not duplicated). If the organization carried a ROR identifier, it is stored with it.
- The affiliation, including any From/To dates the user set, is attached to the submitting user. If the suggestion was an **edit** of one of the user's existing affiliations, that affiliation is updated in place rather than duplicated.
- The user is notified by email.

The suggestion moves to the **Approved** tab.

![Approved suggestions](/img/eln/affiliations/aff-17-admin-approved.png)

## Reject

Click **Reject** to decline the suggestion.

- Nothing is added to the registry.
- If the suggestion was an edit, the user's original affiliation is left unchanged.
- The user is notified by email and keeps whatever affiliation they had before.

The suggestion moves to the **Rejected** tab.

:::note
Users can also withdraw their own pending suggestions before you act on them, in which case the suggestion simply disappears from the **Pending** queue. If two reviewers act on the same suggestion at nearly the same time, the second action shows an "Already processed" message rather than silently succeeding.
:::
