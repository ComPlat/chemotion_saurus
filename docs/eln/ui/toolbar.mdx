The toolbar sits above the element list in the [element panel](.#element-panel) and provides a variety of functions to control the Chemotion ELN elements. Its buttons are `Reporting`, `Export`, `Split`, `Transfer`, `Remove`, `Share`, `References` and `My labels`; the search bar and the green <Btn mixed={[faPlus, "CREATE"]} color={"success"}/> button are located to its right. These functions cover adding, copying, deleting, moving, sharing, filtering, importing and exporting.

## Filtering

The user can filter a selected [collection](collections) or even the **All** collection with the filtering bar <img src={require('@site/static/img/eln/ui/toolbar/filter.png').default} alt={"Filter bar"} />.

The user can search the entire collection or selected elements by clicking on <Btn mixed={["All", faSortDown]} color={"secondary"}/> and choosing the desired element (**Samples**, **Reactions**, **Wellplates**, **Screens**) from the menu to appear, where the <Btn mixed={["All", faSortDown]} color={"secondary"}/> is replaced by the corresponding symbol of the element. The menu also shows the option of **Advanced Search**, which will be clarified later on in this chapter.

A search, quick or advanced, only returns elements of the collection that is open, a shared one included, and the suggestions shown while typing come from that collection too. To search across everything the user owns, open **All**.

Possible search terms are **IUPAC** names, **InChI**, **SMILES**, **RInChI**. The user can also use the element **Name** or **Short Label**. Enter the search term and press "Enter" which shows a list of filtered results. While the user is typing their search term, a menu of suggestions appears, and it keeps getting updated throughout typing. Another option will be to use [Ketcher editor](ketcher), which opens when pressing <Btn mixed={[faPen]} color={"primary"}/>, and to draw a structure to perform **Similarity Search** or **Substructure Search**, and to decide the degree of similarity too. When the structure is ready to be used, the user can choose <Btn mixed={["Search"]} color={"primary"}/> or simply <Btn mixed={["Cancel"]} color={"warning"}/>. To cancel the search process or delete the current search term, press <Btn mixed={[faTimes]} color={"danger"}/>

In the **Advanced Search**, the user can **Select search type** which opens a menu to pick from looking up the **EXACT** term, or entering a substring to look up for, and here the substring can either be included for the search (**LIKE (case insensitive substring)**) or excluded (**NOT LIKE (case insensitive substring)**). In both cases, more strict case sensitive searches can be done with **LIKE (substring)** and **NOT LIKE (substring)**. Another menu enables the user to choose the term type. Available options are **Sample Name**, **Sample Short Label**, **Sample External Label**, and **CAS**. Finally, there is the field for the **Search value**. When the user enters all the entries, they should choose <Btn mixed={["Search"]} color={"primary"}/>. If they want to cancel the search, they could choose <Btn mixed={["Close"]} color={"warning"}/>.

:::danger[Caution]

Although the **Advanced Search** states **Sample** in its menus, e.g. **Sample Name**, it could actually be applied to other elements too.

:::

## Organizing elements in collections

### Add elements from one collection to another

Elements from one collection can be added to another one by means of moving or assigning. The elements added to the target collection have the same properties as the original ones. If some elements already exist in the target collection with the same short label as the added elements, only the added elements are kept, i.e. the properties of already existing elements will be updated based on the added ones.

The above mentioned action could be done by selecting the chosen elements and pressing the `Transfer` button <Btn mixed={[faArrowRight, faSortDown]} color={"success"}/>. A menu opens with two options: **Move to Collection** and **Assign to Collection**. Both options will open the following window to **Select a Collection** as a target from a drop-down menu, **or Create a new Collection** by inserting its name in the corresponding field. When the user is done, they are to press <Btn mixed={["Submit"]} color={"warning"}/>.

<img
  src={require("@site/static/img/eln/ui/toolbar/move_to_collection.png").default}
  alt={"Move to Collection"}
/>{" "}

Please note that if the user chooses to **Assign to Collection**, the title of the window will be **Assign to Collection**.

`Move to Collection`: This action results in moving the selected elements from the selected collection to the target one, this means that the moved elements will no longer appear in the original collection.

`Assign to Collection`: This action adds the selected elements to the target collection as well, without copying them, so that the same elements are present in both collections.

When moving, collections that were shared with the user can also be chosen as a target,
grouped under **Shared by \<owner\>**, provided they hold at least the *Add elements*
permission on them; **Assign to Collection** offers only the user's own collections. Both
also offer the **chemotion-repository.net** collection, under *chemotion-repo*, but never
**All**.

Inside a collection shared with the user, elements stay within their owner's collections:
they can only be moved to another collection of the same owner, which also has to be shared
with the user at *Add elements* or above, and moving needs the *Remove elements* permission
on the collection they come from. A target among the user's own collections is refused, so
**Assign to Collection**, which offers only those, does not work from a shared collection.

:::caution

**Move to Collection** is not available from inside the **All** collection. **All**
gathers everything the user owns rather than being a working collection, so there is
nothing to move the elements out of — one of their own collections has to be used instead.
See
[System collections](collections/index.mdx#system-collections).

:::

### Remove elements from a collection

This action can be performed by pressing <Btn mixed={[faMinusSquare]} color={"warning"}/>. A menu opens with two options: **Remove from current Collection** and **Remove from all Collections**. When the user removes [samples](elements/samples) that are associated with other elements such as [reactions](elements/reactions), the other elements still stand, but the deleted samples will not be accessible, e.g. from within a reaction, anymore, and there will be no way to edit them.

`Remove from current Collection`: This action removes the selected elements only from the selected collection, but a copy is kept in the back up collection **All**. The user is asked to confirm their decision via a pop-up window by pressing <Btn mixed={["Remove"]} color={"warning"}/>, or otherwise to press <Btn mixed={["Cancel"]} color={"primary"}/>.

`Remove from all Collections`: This action removes the selected elements from **all of the user's own collections**, and permanently deletes only those elements that are left in no collection at all. It never reaches into a collection owned by someone else, including one that has been shared with them — those keep their copy, and its owner goes on seeing the element. Samples still used in a reaction or a wellplate are kept rather than deleted, and a notice says how many — it does not name them. The action is not offered at all while working inside a collection someone else shared. The user is asked to confirm their decision via a pop-up window by pressing <Btn mixed={["Delete"]} color={"warning"}/>, or otherwise to press <Btn mixed={["Cancel"]} color={"primary"}/>. An option is provided in case the user is trying to remove reactions, which is to choose whether to delete the samples associated with the reactions, if the user chooses not to, then only the reactants and solvents associated with the deleted reaction are deleted too.

### My labels

Labels can be added to or taken off a whole selection at once. Select the
elements, then press **My labels** at the right-hand end of the toolbar, which
opens **Bulk edit user labels**.

The window offers two lists — **Add labels** and **Remove labels** — and
**Apply to selection** carries both out across every selected element,
whatever their type. Only the user's own labels and any global ones are
offered, and other people's private labels on those elements are left alone.

The button needs a selection, and edit rights in the current collection.

:::note

The labels themselves are created and edited under **My Labels** in the user
menu. The two names are nearly the same: the toolbar button works on a
selection, the user-menu entry maintains the list.

:::

## Sharing collections

Collections can be shared with individual users and with groups, at a permission level the
owner chooses. To share the collection currently open, press
<Btn mixed={[faShareAlt]} color={"info"}/>; to share just a selection of elements as a new
collection, select them and choose **Share** from the selection actions.

The permission levels, the detail levels, and everything else about the sharing model are
described in [Sharing Collections](collections/sharing).

## Import and Export Data to and from the Chemotion ELN

Exporting data from the Chemotion ELN can be done using the `Export` button in the toolbar. Importing data uses a separate control: it is triggered from the three-dot menu next to the collection's name in the collections sidebar, not from the toolbar, and is described separately below.

### Exporting data

The user can export either selected elements from a collection in the form of files, or export collections as zip.

To export elements, go to the collection that contains them, and select the desired elements. From the exporting icon in the toolbar, pick **Export samples from selection**. Please pay attention that not only samples can be exported with this option but also reactions, wellplates, and analyses. If multiple types of elements were to be exported as an XLSX, they are sorted in different sheets in the file.

## Reporting and Literature Organization

### Report


:::note[Custom report templates]

Report layouts come from template files shipped with the ELN, chosen by report
type. Replacing one is a server-side change to the installation, and an upgrade
overwrites it.

A replacement `.docx` must define the `ListBullet` and `ListNumber` paragraph
styles. Without them, generating a report fails whenever a selected element
contains a bulleted or numbered list in a rich-text analysis.

:::

This icon <Btn mixed={[faCaretSquareRight, "Reporting", faSortDown]} color={"light"}/> helps the user to produce reports and organize the literature in their data. The same dropdown also offers QR code, Data Matrix code, and Bar code generation, Format Analyses, and — where the instance administrator has enabled it — the **Explorer**.

### Explorer

The Explorer draws the open collection as a graph, so that the relationships
between its samples and reactions can be seen at once. It needs no selection:
it always shows the whole collection, and opens as a card in the details pane.

Reactions appear as red boxes labelled with their short label and name, newest
first. Around each one sit its starting materials and products, joined to it by
labelled edges, with its reactants and reagents beside it. A sample that is the
product of one reaction and the starting material of the next is drawn once, so
a multi-step sequence stays connected, and a split sample is joined to the one
it came from. Samples belonging to the collection but used in none of its
reactions are stacked in a column at the left, solvents among them.

A search box matches reaction and sample labels and names, and samples by
canonical SMILES. A match also brings in the reactions that sample takes part
in.

:::note

The Explorer is new in version 4.0 and is one of the optional interface
components, switched off by default in a production instance. It appears only
where an administrator has enabled it.

:::

Users can report the elements they have by selecting them and clicking on **Report**, this will open the window above. From the **config** tab, choose from **Template selection**. This choice affects the fields in the other tabs and the **File Name** that is given to the file by default. This ** File Name** includes the date of report generation which can still be edited by the user. In all the templates a field for **File description** is provided. In the **Setting** tab the user can choose what properties to add to the report. In the **Order** tab the user can resort the elements by using the symbol <Btn mixed={[faArrowsAlt]} color={"secondary"}/>, and can also delete elements from the report with <Btn mixed={[faTimes]} color={"danger"}/>. ## Creating Elements

The generation of new element-instances such as a new sample or a new reaction can be done by three different actions: **add**, **copy** and **split**. The function add is available for all types of elements, the functions copy and split are only available for selected ones.

### New elements with the "CREATE" button

New elements are created with the green <Btn mixed={[faPlus, "CREATE"]} color={"success"}/> button to the right of the toolbar. Clicking it opens a menu with the options **Create Sample**, **Create Reaction**, **Create Wellplate**, **Create Screen** and **Create Research Plan**. It does not matter which element list is selected, as long as the right collection is open — choose any of these options and the corresponding element is created. The button is disabled in the **All** collection, which is not a working collection (see [System collections](collections/index.mdx#system-collections)). In a collection shared with the user, creating an element needs at least the *Add elements* [permission level](collections/sharing.mdx#the-permission-ladder).

To populate [wellplates](elements/wellplates), the user has to drag and drop samples, and to populate screens, the user has to drag and drop wellplates. The `CREATE` menu lets the user avoid this repetitive drag-and-drop process with the functions **Create Wellplate from Samples** and **Create Screen from Wellplates**. To use either of them, go to the target collection, select the elements (samples or wellplates) to be added to the newly created element (wellplate or screen respectively), and choose the corresponding function. The menu also offers **Create Vessel Template**. Please note that an element cannot be created with this method from elements coming from another collection; users can, however, still add them to the created element with the classical drag and drop.

### Function "copy" or "split" for samples

Generation of new samples with molecular structures that are already used by other samples can be carried out by two similar but not equal actions, **Copy** and **Split Sample**.

To copy a sample, open its details view and press the clone icon <Btn mixed={[faClone]} color={"secondary"}/> in its header. A **Copy** dialog opens where the user picks the target collection and presses **Copy** to create the copy there.

:::danger[Caution]

With the **Copy** action, only the molecular structure of the sample is copied; all other information is not available and will not be adopted. Only the general data available from the molecular structure are transferred.

:::

Split is done from the collection list: select the elements whose structure is to be split, then use the `Split` button <Btn mixed={[faCodeFork, faSortDown]} color={"light"}/> from the toolbar. A menu opens with an entry for each selected element's type, e.g. **Split Sample**, **Split Wellplate**, **Split Cell line**, **Split Device Description**, or **Split Sequence Based Macromolecule Sample**.

When creating a new sample using the split function **Split Sample**, a new sample is created that is directly dependent on the original sample. In contrast to copy, with split not only the structure-dependent information of the original sample is taken over for the creation of a new sample. All available data are used to generate the new sample. The action is intended to represent those cases in the laboratory in which something is removed from a batch and used for a new purpose. Examples of a split action are therefore e.g., the removal from a chemical container or the further use of a product from a reaction. For more details on Samples generation, visit this [link](elements/samples#generation).

### Function "copy" for reactions

Reactions are copied the same way as samples: open the reaction's details view and press the clone icon <Btn mixed={[faClone]} color={"secondary"}/> in its header, then pick the target collection in the **Copy** dialog and press **Copy**.
