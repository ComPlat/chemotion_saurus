## Creating Inventory for a Group

Creating a chemical inventory that can be accessed by all members of a working group requires four steps:

1. [creating a new user](#creating-a-new-user),
1. [creating a collection in that user's Chemotion ELN and adding all chemicals to that collection as samples](#creating-a-new-collection),
1. [creating a new group or adding the account to an existing group](#creating-a-new-group) and
1. [sharing the collection with the group](#sharing-the-collection-with-the-group).

After creating an inventory, one can proceed to [creating entries](#creating-chemical-entry) in it.

### Creating a new user

A new Chemotion ELN account should be created to manage the chemical database. All new chemicals will need to be created by that account (usually that account is managed by the person in charge of ordering chemicals or receiving the group's chemicals). Once a chemical has been created in that account as a sample it can be edited by any group member (for example to update the amount left in the bottle), if the collection is shared with the right privileges (more on this in the section [sharing the collection with the group](#sharing-the-collection-with-the-group)).  
The registration process of that account is identical to registering any other new Chemotion ELN user.

### Creating a new collection

In the newly created account, a [collection](collections) has to be created where all chemicals can be inserted as [samples](elements/samples). If the group is located in different buildings, or uses different chemical subsets, multiple collections can be created for the different buildings or subsets. Each collection can be shared with one or more groups independent of one another.
Once the collection is created, the chemicals that are part of the database have to be created as samples. Importing a database is possible using the [`import samples to collection` function](toolbar#importing-data) of the Chemotion ELN. For that purpose, an XLS or XLSX Document in the right format and containing all chemicals to be imported, must be available.  
It is advisable to create the samples with all relevant information in the `Properties` tab, such as CAS number, concentration or molarity, density, etc. However, the information can be updated later by other users, if the collection is shared with the group at the *Edit elements* level (more on this in the section [sharing the collection with the group](#sharing-the-collection-with-the-group)).

### Creating a new group

It is advisable to share the collection containing the chemical database with a group, not with individual users, as it makes management easier. The group does not have to be created by the same account managing the chemical database. However, both can be also managed by the same account.
To create a new group, choose `My groups and Devices` from the drop-down menu on the top right corner by clicking on the account's name next to the sign-out button.
Now proceed to create a new group and then add all group members who should have access to the database of the new group. Multiple groups can be created, if different collections, containing subsets of the chemical database, are to be shared with different group members.  
Note that only the person who created the group, or the account the administrator rights were transferred to, will be able to manage group members.

### Sharing the collection with the group

From the collection's menu, choose **Add share** and share the collection containing the
chemical database with the group.

Choose the permission level with care, as it decides what group members may do with the
inventory:

- **Edit elements** lets members update existing chemicals — the amount left in the bottle,
  the storage location, concentration or molarity, and so on. This is the usual choice.
- **Add elements** additionally lets members create new chemicals themselves. Pick this
  only if ordering is not centralized in the managing account.
- **Read elements** is enough if members should only look up chemicals, never update them.

Members also need the **full detail level** for samples in order to edit them, so set the
sample detail level accordingly.

Sharing with the group rather than with each person individually means access follows group
membership: adding someone to the group grants them access, and removing them withdraws it.
For the whole sharing model, see [Sharing Collections](collections/sharing.mdx).

## Creating Chemical Entry

There are three ways to create an entry in the inventory:

### Creating a new sample

A chemical Entry can be created by creating a new sample as an inventory entry. Please refer to [Generate Sample](elements/samples#generation) section, to learn how to create a new sample. Once a new sample is created, the user can check the inventory check box to enable handling of a sample as a chemical entry.

### Splitting sample for chemical entry

The process of creating a chemical entry in the Electronic Laboratory Notebook (ELN) involves initially creating a sample.
However, users also have the option to generate a new chemical entry through the [Split Sample](elements/samples#generation-of-samples-from-existing-samples-or-molecules) feature.  
For further information on how to utilize this feature, please consult the [Split Sample](elements/samples#generation-of-samples-from-existing-samples-or-molecules) section.
When a split sample is performed, the newly generated chemical entry inherits the data from the original entry.
Subsequently, users are able to modify the data according to their specific requirements.

</video>

### Drag and drop chemical entry

Users have the capability to employ a drag-and-drop action to transfer a chemical entry from the inventory list to a [reaction](elements/reactions), thereby generating a subsample derived from the original chemical entry.
In this process, only safety information pertaining to the subsample is generated.
Subsequently, users can conveniently navigate to the inventory tab of the created subsample to access and review the corresponding safety information.

## Managing Inventory

The inventory tab will appear in the Tabs Layout. The user can make the inventory tab visible by drag and drop, if it is hidden by default. Once the inventory tab is active, the user can start entering chemical data in the corresponding fields.

<video controls>
  <source src={require("@site/static/img/eln/ui/inventory/inventory_tab.webm").default} />
</video>

** The inventory tab is organized into a hierarchical structure consisting of three collapsible lists, outlined below: **

1. [Inventory Information List](#inventory-information-list),
1. [Safety List](#safety-list),
1. [Location and Information List](#location-and-information-list)

This structure enables convenient navigation and organization of data for a chemical inventory entry.

### Inventory Information List

This section contains the following fields:

- `status:` List of 4 options for status of the chemical (available, out of stock, to be ordered, and ordered).
- `vendor:` The vendor associated with the chemical order.
- `order number:` The order number of the chemical.
- `product number:` The vendor's product number for the chemical.
- `price:` The price of the ordered chemical.
- `person:` Contact person associated with the chemical.
- `required date:` The date when person or entity required the chemical.
- `ordered date:` The date when the chemical was ordered.
- `expiration date:` The date given by vendor when the chemical will expire.
- `delivery date:` The date the chemical was delivered.
- `opening date:` The date the container was opened.
- `required by:` The person or entity that required or ordered the chemical.
- `amount:` Specifies the amount of the chemical, with unit (mg, g, or μg).
- `volume:` Specifies the volume of the chemical, with unit (l, ml, or μl).
- `storage temperature:` The temperature given by vendor at which the chemical should be stored. The unit button switches between °C, °F and K, converting the value.
- `inventory label:` The label assigned to the chemical within its collection.

:::info[Decimal commas, from version 4.0]

The amount, volume, storage temperature and flash point fields accept a comma
as the decimal separator, so `2,5` is stored as 2.5. Earlier versions ignored
the comma, which made such a value impossible to enter. Thousands separators
are not supported: `1,234` is read as 1.234, and a hint under the field says
so.

:::

### Safety List

- The Safety section is an interactive feature that allows users to search for and access safety data sheets (SDS) and safety phrases related to specific chemicals.
- Users can select the vendor associated with their query, choosing from the <Btn mixed={["Vendor"]} color={"secondary"} /> drop-down list: **Sigma-Aldrich**, **Thermofisher** and **All vendors (PubChem)**. The last searches PubChem's own list of vendor sheets rather than the vendors' websites, and presents the results grouped by vendor.
- The <Btn mixed={["Query SDS using"]} color={"secondary"} /> button provides a dropdown list for users to select whether to search using the CAS (Chemical Abstracts Service) number, the common name, or the **Product Number** of the chemical.
- The <Btn mixed={["Choose Language of SDS"]} color={"secondary"} /> dropdown list offers three language options: English, German, and French. If no results are found with the chosen language, results will be displayed with the default query language (English).
- After selecting the search parameters, users can initiate the search query by clicking the <Btn mixed={["Search for SDS"]} color={"secondary"} /> button.
- The search results will be displayed, each titled `Safety Data Sheet from <vendor> - <number>`, and users can click one to open a new tab directing them to the vendor's safety data sheet.
- It is recommended for users or administrators to first verify if the displayed results are associated with the desired chemical.
- If results match the specific chemical, users can save the safety sheet to the Electronic Laboratory Notebook (ELN) by clicking the save button next to the relevant result tag. A green check mark icon will appear next to the result element tag, if SDS is saved successfully, and the sheet moves into the `Safety Sheets saved in the database` list below.
- Once saved, the sheet can be read with **Extract from sheet**, described below.
- Users have the option to delete the saved data sheet by clicking the delete icon <Btn mixed={[faTrash]} color={"danger"}/> button.
- Up to **five** sheets can be saved per sample, counted as `n of 5` above the saved list. Searching stays available throughout, and a sheet already saved is not saved twice.
- Additionally, users can access the vendor's product webpage by clicking the external link icon <Btn mixed={[faExternalLink]} color={"secondary"} /> button.
- Each saved sheet carries an **Extract from sheet** button, which reads the sheet itself rather than querying the vendor again.

#### Extract from sheet

From version 4.0, **Extract from sheet** replaces the former *fetch safety
phrases* and *fetch Chemical Properties* buttons. It reads the text of a sheet
already saved against the chemical and takes two things from it:

- the **H and P codes** from the label-elements section, along with the
  pictograms those codes imply, which go into the
  [safety phrases editor](#adding-safety-phrases-manually);
- the **physical and chemical properties** from section 9 — melting point,
  boiling point, flash point, density, form, color, refractive index and
  solubility among them — some of which are written straight into the sample's
  **Properties** tab.

The button sits on every row of the saved list; on a search result it is
disabled until the sheet is saved. While it runs it reads *Reading sheet…*, and
one sheet is read at a time. A notice afterwards says what was found, what was
set, and what was skipped because it was not in a unit the sample accepts.

Everything read is kept with that sheet and can be reviewed later with the
document button beside it, which opens **Fetched Chemical Properties**.

:::note[Properties are saved at once; phrases are not]

Properties written into the **Properties** tab are sent to the server
immediately, as a save of the whole sample — so any unsaved edits elsewhere on
that sample are written too. The H and P phrases and the pictograms behave
differently: they are placed in the editor and need the sample to be saved
before they persist.

:::

:::caution[An extraction replaces the existing phrases]

When codes are found, they replace the whole set of H and P phrases and
pictograms, rather than being added to it. When none are found, what is already
there is kept.

:::

Sheets from **Sigma-Aldrich** (also Merck and MilliporeSigma) and **Thermo
Fisher** (also Fisher Scientific, Acros Organics and Alfa Aesar) are
recognized, in English or German. Recognition is based on the content of the
sheet rather than the vendor recorded at upload, so a manually uploaded sheet
from one of those vendors is read as well. A sheet that cannot be used — a
scanned one with no text, or another vendor's layout — is reported with the
reason.

:::note

Despite the wording used on screen, no AI is involved: the ELN reads the text
layer of the PDF. An instance may be configured to hand this to a separate
[PDF text service](../install-configure/configuration#safety-data-sheet-text-extraction);
where it is, and that service is unavailable, extraction reports an error
rather than falling back to reading the sheet locally.

:::

### Adding safety phrases manually

Safety phrases do not have to come from a safety data sheet. The safety section contains an editor that
lets users curate the safety phrases of a chemical entry by hand, which is useful when no safety data
sheet (SDS) can be found, when an extraction returns incomplete results, or when a substance is
prepared in-house.

The editor sits under the heading **Safety phrases and pictograms** at the foot of the safety section.
When nothing has been set it starts collapsed, labelled *none added yet*, and each of its three parts —
**Hazard Statements**, **Precautionary Statements** and **Pictograms** — likewise starts collapsed
while it is empty and opens by itself once it has content. Each heading and each row carries a copy
button.

It is organized into three parts:

- **Hazard Statements** — the H-codes of the chemical (for example `H225`).
- **Precautionary Statements** — the P-codes of the chemical (for example `P210`).
- **Pictograms** — the GHS hazard pictograms (`GHS01` to `GHS09`), displayed as images.

![Safety phrases editor](/img/eln/ui/inventory/safety_phrases_editor.png)

The editor panel is limited in height and scrolls internally, so a chemical with
many statements does not push the rest of the inventory tab out of view. The
screenshot above shows all three sections at once; in the running ELN the lower
sections may have to be scrolled into view.

#### adding a phrase

1. Open the inventory tab of the chemical entry, expand the safety list, then
   **Safety phrases and pictograms** and the part to be edited — each is
   collapsed while it is empty.
1. Click the search field of the section that should be extended (hazard statements, precautionary
   statements, or pictograms).
1. Type a code or a part of the phrase text. The drop-down filters the list of available entries while
   typing; codes that are already assigned to the chemical are not offered again.
1. Select the desired entry from the drop-down. It is added to the list below the search field
   immediately.
1. Click the save button at the bottom of the inventory tab to persist the changes together with the rest
   of the inventory data.

<video controls>
  <source src={require("@site/static/img/eln/ui/inventory/add_safety_phrase_manually.webm").default} />
</video>

New entries are appended to the end of their list rather than sorted into it, so
the order of the list reflects the order in which the phrases were added.

The selectable codes are taken from the GHS dictionaries shipped with the ELN. Besides the plain H- and
P-codes, these dictionaries also contain the combined codes (for example `H300+H310` or `P301+P310`) and
the European supplemental hazard statements (`EUH` codes), so these can be selected as a single entry
instead of being assembled from their parts.

#### removing a phrase

Each entry in the hazard and precautionary lists carries a delete button
<Btn mixed={[faTrash]} color={"danger"} />, and each pictogram card carries the same button in its upper
right corner. Clicking it removes that entry from the chemical entry. As with adding a phrase, the removal
becomes permanent only after the inventory tab is saved.

<video controls>
  <source src={require("@site/static/img/eln/ui/inventory/remove_safety_phrase.webm").default} />
</video>

:::caution

A **successful** extraction replaces the complete content of the editor: if
[Extract from sheet](#extract-from-sheet) finds H and P codes, they overwrite the lists and the
pictograms, so manual additions and removals made before it are lost. It is therefore advisable to
extract first and to refine the result by hand afterwards.

An extraction that finds no codes leaves the existing phrases untouched — only a notice is shown and
the editor keeps its content.

:::

### Attach Safety Sheets manually

This feature allows users to manually attach Safety Data Sheets (SDS) to chemical samples. It provides a user-friendly interface for uploading files and entering relevant metadata, ensuring that safety information is properly associated with the chemical.

### Overview

The manual SDS attachment functionality allows users to:

- Upload a PDF file as the SDS.
- Provide metadata such as product number, vendor name, product link, and safety sheet link.
- Validate some inputs to ensure data integrity.

### Key Features

- **File Upload**: Restricts file uploads to PDF format.
- **Input Fields**:
  - Product Number
  - Vendor Name
  - Product Link (optional)
  - Safety Sheet Link (optional)
- **Validation**:
  - Ensures required fields are filled.
  - Validates URLs for product and safety sheet links.
  - Displays error messages for invalid inputs.

### Workflow

1. Click the green <Btn mixed={[faPlus]} color={"success"}/> button at the left of the safety control row, whose tooltip reads *Attach a safety data sheet from your computer*.
2. Fill in the required fields and upload a PDF file.
3. Click "Submit" to save the attachment.

<video controls>
  <source src={require("@site/static/img/eln/ui/inventory/manual_sds_attachment.webm").default} />
</video>

### Validation Rules

- **File Type**: Only PDF files are allowed, up to 10 MB.
- **Product Number**: Between 2 and 25 characters.
- **Vendor Name**: Between 2 and 20 characters — lowercase letters, digits and hyphens, starting with a letter, with no hyphen at either end and none doubled.
- **URLs**: Must be valid URLs if provided.

A manually attached sheet counts toward the limit of five sheets per sample,
and can be read with [Extract from sheet](#extract-from-sheet) like any other.

### Error Handling

- Displays error messages for invalid inputs.
- Prevents submission if required fields are missing or invalid.

### Location and Information List

The Location field is divided into 2 subsections `host location, host group`, which reflects information about owner of chemical and `current location, current group` in case chemical is borrowed by another group/person. Both subsections have overlapping fields.

- `building, room, cabinet` where the chemical is stored.
- `group:` related to the chemical.
- `owner:` the person responsible for the chemical.
- `by:` the person who borrowed the chemical.

![location and information list](/img/eln/ui/inventory/location_info_save_chemicalTab.png)

User can use `Disposal information` field to save any information related to the disposal of the chemical or use `important notes` field to save any other relevant information. The user can click the save button after making any changes or updating any field inside the inventory tab to save the changes. The save button is located at the bottom of the inventory tab.

## Import and Export Chemicals

The Import and Export of chemical data functionality has been integrated into the core ELN export/import data feature within the Chemotion ELN platform. For a comprehensive understanding of the fundamental procedures involved in importing and exporting various elements and samples within the ELN system, users can check the [Import and Export data](toolbar?-highlight=xlsx#import-and-export-data-to-and-from-the-chemotion-eln) section.
Users are provided with the flexibility to choose between exporting/importing individual chemical samples or multiple selected samples. Export and import are reached through two separate paths:

- **Export** uses the `Export` button in the collection toolbar ![Export Menu](/img/eln/ui/inventory/action_bar_import_export.png), which offers **Export samples from selection** and **Export reactions from selection**. Chemical entries are exported with the **Export samples from selection** option.
- **Import** is not part of the toolbar. It is started from the dropdown menu next to a collection's name in the collection tree on the left, using the **Import samples to collection** entry.

Chemical samples are imported from an XLS/XLSX sheet and exported as XLSX or SDF.

1. [Export Chemicals](#export-chemicals)
1. [Import Chemicals](#import-chemicals)

### Export Chemicals

To initiate the export of a chemical sample, the user selects the chemical entries in the collection and picks **Export samples from selection** from the `Export` button in the toolbar.
This opens the **Select Data to Export** dialog, in which the fields to be exported are grouped into sections: Sample properties, Molecule properties, Reaction properties, Wellplate and well properties, Analyses, **Chemicals**, and Components.
The **Chemicals** group holds the inventory fields (status, vendor, order number, amount, price, person, required date, ordered date, expiration date, delivery date, opening date, storage temperature, required by, safety sheet link, product link, pictograms, h statements, p statements, host building, host room, host cabinet, host group, owner, current building, current room, current cabinet, current group, borrowed by, disposal info, and important notes) and has its own `Select all` checkbox, so all chemical properties can be selected at once.
Additionally, the user can opt to include further sample or molecule properties to the exported sheet. To run the export, press <Btn mixed={["XLSX/SD Export"]} color={"warning"} /> and choose either **XLSX Export** or **SDF Export**. An example of export chemical process is shown below.

### Import Chemicals

To start the import of chemical samples process, users should follow these steps:

- In the collection tree on the left, open the dropdown menu next to the name of the collection the chemicals should be imported into. It contains the entries `Reference Report` and `Import samples to collection`.
- Click `Import samples to collection`. The dialog **Import samples from file to \{collection name\}** opens, which is the interface for uploading the chemical sheet. There is no separate chemical import: chemical entries are imported through this same sample import, using the chemical columns of the template below.
- It is strongly recommended that users utilize the provided chemical template below, as importing chemicals necessitates specific data points. In order to import a sample into Chemotion ELN, it is generally required to have at least one of the following columns present in the import data:
  Canonical SMILES (SMILES) or Molfile. While the remaining columns are optional, providing more details is encouraged for comprehensive record-keeping.
- Additionally, users have the capability to import safety data sheets into Chemotion ELN by entering relevant information into the designated fields such as safety data sheet and vendor. Please note that this option is presently compatible only with the Merck vendor.
- Importing is also feasible for samples and chemicals that do not possess a chemical structure (referred to as decoupled samples). In such instances, users should indicate the value yes in the column of decoupled. If the sample has chemical structure, it is imperative to ensure that any of the columns relevant to the chemical structure, such as molfile and canonical SMILES contain valid data.

:::info[Recommendation]

For the import process of a chemical inventory entry, **Amount** in the inventory tab should be entered using the column header labeled **Amount**, which refers to the amount of the chemical inventory entry in grams.

The **Target/Real Amount** column headers, however, refers to the **Amount** field in the [**Sample Properties tab**](https://chemotion.net/docs/eln/ui/details?_highlight=properties&_highlight=tab#properties-tab), which is specific to the sample and not related to the inventory entry.

:::
